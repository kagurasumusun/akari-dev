# tools/verify-ptr-known.txt -- the pointer-audit ledger.
#
# One `<regex><TAB><reason>` per line.  verify-ptr.py checks every live
# declaration in include/ against the print on the page the declaration
# cites; a mismatch that matches a pattern here is *explained*, not
# fixed: the tree is never edited from an unconfirmed print (project
# rule: no definition without an official page behind it).
#
# M107b pass (3755 declarations checked; 33 residuals, all classified
# below).  Two of them were real tree bugs and were fixed in the tree
# instead of being listed here:
#   * ms896134 BatteryNotifyOfTimeChange -- print `FILETIME *pftDelta`,
#     the tree had lost the star (include/Pwinuser.h).
#   * the whole Spl* family of the first M107b generation run -- the
#     gen-book parameter-splitter bug (fixed in tools/gen-book.py).
#
# class 1: the archive's own print lost a star or a type token (the page's
#          parameter description says "pointer to ...", so the tree's
#          compiled form is the documented one, not the print's)
_wcesdk_COM_CoTaskMemFree	CoTaskMemFree: print `void CoTaskMemFree( void pv )` -- the page's own text says "Pointer to the memory block to be freed"; the tree uses LPVOID pv (same type as the documented one)
ms886940	CoTaskMemFree: same page text as above, print lost the `LPVOID` token
wcesdkrRasSetEntryProperties	RasSetEntryProperties: the print glues the parameter name into the type (`LPWSTR szEntr` vs `LPWSTRszEntr`); the tree's parameter list is the print's
_wcesdk_crypto2_CryptDuplicateHash	CryptDuplicateHash: print `HCRYPTHASH phHash` for an [out] parameter whose description reads "Pointer to the handle to the duplicated hash" -- the tree's HCRYPTHASH* is the documented parameter
_wcesdk_Win32_CreateDIBSection	CreateDIBSection: print `void * ppvBits` for the [out] parameter that receives the bitmap-bits pointer; the CE/Win32 ABI for that parameter is a pointer to a pointer (tree: void**)
_wcesdk_VarBstrFromDec	VarBstrFromDec: print spells the [out] BSTR parameter without its star (the same page's PARAMETERS table describes an address); tree: BSTR*
_wcesdk_VarUdateFromDate	VarUdateFromDate: this SAL page prints `unsigned long * dwFlags` while page ms891856 prints `unsigned long dwFlags` for the same function of the same header (Oleauto.h). The two official prints contradict each other; the tree follows ms891856 (which also matches the OA96 ABI)
ms891856	VarUdateFromDate: see the note above -- the tree follows this page
_wcesdk_oa96_SystemTimeToVariantTime	SystemTimeToVariantTime: the print is glue-damaged (`SYSTEMTIMElpSystemTime`); the tree's LPSYSTEMTIME is the documented type
ms891294	SystemTimeToVariantTime: same glue-damaged print as above
